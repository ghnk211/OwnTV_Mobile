## 1. 需求与改造原则

用户反馈：**设置页的设置项太多、太分散**，需要重新归类排序。

本方案只做「归位 + 排序 + 合并小组」，边界如下：

1. **不删除任何设置项**，不删除任何存储 key，不改动行 key（`SettingItem.key`）。
2. **core 零改动、不发版**；组标题与 Section 标题全部复用现有 `R.string.*`，**不新增 i18n 文案**。
3. Quick 固定、设置搜索、TV 备份互认、前三轮 `applySlimXxxDefaults` 收敛机制全部保持不变。
4. 保留「观看与录制」页现有结构，与第四轮收敛方案（`docs/观看与录制设置页改造方案.md`）兼容。

## 2. 现状诊断

### 2.1 现状规模

根页 `SettingsGroup` 共 **11 组**（`SettingsCommon.kt:33-53`），枚举顺序即卡片顺序，两列铺卡（`SettingsScreen.kt:96-107`）：

| # | 组 | 组页可见行数 | 叶子页 |
|---|---|---|---|
| 1 | QUICK 快速 | 动态（按 pin） | — |
| 2 | SOURCES 来源与指南 | 8（含 1 条件行） | 播放列表 / Add source / EPG 源 / 回看时区 |
| 3 | APPEARANCE 外观 | 3 | 玻璃与背景 / 字体 |
| 4 | LAYOUT 布局 | 7 | 首页 / 浏览与列表 / 内容菜单 |
| 5 | CONTENT 内容与元数据 | 4 | 自定义 / 元数据 / OpenSubtitles |
| 6 | PLAYER 播放器 | 2 | 外部播放器 |
| 7 | PICTURE 画面 | 4 | — |
| 8 | SOUND 声音和字幕 | 2 | 字幕外观 |
| 9 | LIVE 直播电视 | 3（含 2 条件行） | — |
| 10 | WATCHING 观看与录制 | 6 | — |
| 11 | APP 应用 | 12 | 语言 / 应用锁 / 代理 / DNS |

### 2.2 三个问题

1. **小组占大卡**：PICTURE 只有 4 行、SOUND 只有 2 行、LIVE 只有 3 行，却各占一张根页卡片；根页 11 张卡片里有 4 张点进去不足 5 行。
2. **同类设置分散**：
   - 「画面」（硬件解码、SDR、缩放）与「播放器」（外部播放器、重连）本是一件事，被拆成两组；
   - 「布局」（导航、首页、浏览、菜单）与「外观」（主题、玻璃、字体）同属界面个性化，被拆成两组；
   - 「内容与元数据」（儿童模式、自定义、元数据）与「来源与指南」同属内容侧，被拆成两组；
   - 「OpenSubtitles 字幕账号」在「内容与元数据」组，而「字幕外观」在「声音和字幕」组，同一个字幕主题两处找。
3. **顺序不符合使用路径**：外观、布局排在播放类之前；「应用」组内又混入了网络与下载，组名与内容不匹配。

## 3. 目标结构：11 组 → 8 组

### 3.1 根页顺序

| # | 新组 | 由哪些原组合并 | 组标题（复用 core 资源） |
|---|---|---|---|
| 1 | QUICK 快速 | QUICK | `settings_group_quick` |
| 2 | SOURCES 内容与来源 | SOURCES + CONTENT（OpenSubtitles 除外） | `settings_group_sources` |
| 3 | PLAYER 播放与画面 | PLAYER + PICTURE | `settings_vp_cat_player` |
| 4 | SOUND 声音与字幕 | SOUND + OpenSubtitles | `settings_group_sound_subtitles` |
| 5 | LIVE 直播电视 | LIVE（不变） | `settings_live_tv` |
| 6 | WATCHING 观看与录制 | WATCHING（不变） | `settings_group_watching_recording` |
| 7 | APPEARANCE 外观与布局 | APPEARANCE + LAYOUT | `settings_appearance_group` |
| 8 | APP 应用 | APP（不变，仅位置后移） | `settings_app_group` |

根页两列布局变为 4 行：

```
第0行: QUICK        | SOURCES
第1行: PLAYER       | SOUND
第2行: LIVE         | WATCHING
第3行: APPEARANCE   | APP
```

排序逻辑：**先内容源，再播放与声音，再直播与录制，然后是个性化外观，最后是应用与系统级设置**。

### 3.2 文案策略：零新增

被合并掉的三个组标题原地降级为 Section 标题，不新增任何字符串：

| 原组标题资源 | 新用途 |
|---|---|
| `settings_group_content_metadata` | SOURCES 页「内容与元数据」Section 标题 |
| `settings_vp_cat_picture` | PLAYER 页「画面」Section 标题 |
| `settings_group_layout` | APPEARANCE 页「布局」Section 标题 |

代价：被删除的 3 个组卡片说明（`settings_card_content` / `settings_card_picture` / `settings_card_layout_mobile`）不再展示；合并后 3 个组的卡片说明文案（Sources & guide / Player / Appearance）覆盖范围略窄。按第四轮「摘要文案可接受过期」的口径处理，不改 core。

## 4. 逐页目标顺序

### 4.1 QUICK（不变）

pin 列表顺序完全不变。`QUICK_ALIASES` / `QUICK_WORDS` 不动。

### 4.2 SOURCES 内容与来源（11 行）

| Section | 行 |
|---|---|
| 「来源」`settings_sources_title` | 播放列表 `tab_SOURCES` → EPG 源 `tab_EPG` |
| 「指南与回看」`settings_part_guide_catchup` | EPG 时间偏移 `epg_offset` → 提醒 `reminders` → 提醒提前量 `reminder_lead` → 指南保留天数 `guide_days` → 回看 `catchup` → 每个播放列表的回看时区 `catchup_sources`（条件行） |
| 「内容与元数据」`settings_group_content_metadata` | 儿童模式 `kids_mode` → 自定义 `tab_CUSTOMIZE` → 元数据 `tab_METADATA` |

> OpenSubtitles 从本组移到 SOUND 页。

### 4.3 PLAYER 播放与画面（6 行）

| Section | 行 |
|---|---|
| 「画面」`settings_vp_cat_picture` | 硬件解码 `vp_hw` → 偏好 SDR `vp_hdr` → 默认缩放 `vp_zoom` → 已保存的缩放 `vp_reset_zoom` |
| 「播放器」`settings_vp_cat_player` | 外部播放器 `vp_external` |
| 「串流」`settings_vp_cat_streaming` | 点播重连 `vp_vod_reconnects` |

> 画面段放最前，因为它是本组最常被调整的一组；外部播放器与重连各保留原 Section，语义不变。

### 4.4 SOUND 声音与字幕（3 行）

单 Section（无标题，保持现状）：

1. 环绕音 `vp_surround`
2. 字幕外观 `vp_sub_style`
3. OpenSubtitles `tab_OPEN_SUBTITLES`（从 CONTENT 移入）

顺序按「本机设置 → 外部字幕服务」排列。

### 4.5 LIVE 直播电视（不变）

时移 `vp_timeshift` → 时移窗口 `vp_timeshift_window`（条件）→ 时移恢复 `vp_timeshift_resume`（条件）。

### 4.6 WATCHING 观看与录制（不变）

继续播放 `vp_resume`；录制 5 项 `rec_reserve` / `rec_mobile_data` / `rec_watching` / `rec_pre_roll` / `rec_post_roll`。

与第四轮收敛方案的目标结构一致，后续实施不受本次重排影响。

### 4.7 APPEARANCE 外观与布局（10 行）

| Section | 行 |
|---|---|
| 无标题（沿用现状） | 主题 `theme` → 玻璃与背景 `tab_GLASS_EFFECT` → 字体 `fonts` |
| 「布局」`settings_group_layout` | 导航 `navigation` → 直播打开方式 `live_opens_in` → 点播视图 `vod_view` → 首页 `tab_HOME` → 浏览与列表 `browsing_lists` → 内容菜单 `tab_CONTENT_MENUS` → 指南尺寸 `guide_size` |

### 4.8 APP 应用（不变，位置移到末位）

| Section | 行 |
|---|---|
| 「应用」`settings_app_group` | 语言 → 应用锁 → 应用图标 → 品牌强调色 → 启动 → 检查更新 → 更新启动 |
| 「网络」`settings_group_network` | 代理 → DNS |
| 「下载」`common_nav_downloads` | 允许下载 → 下载文件夹 → 仅 Wi-Fi |

## 5. 代码改动点

### 5.1 核心策略：拼接而不重写

各页的行构建函数（`sourcesSections` / `contentSections` / `playerSections` / `pictureSections` / `appearanceSections` / `layoutSections` / `soundSections`）**全部保留**，只在 `groupSections()` 分发处用 `+` 拼接。这样：

- 行 key、行顺序、setter 调用一行不动；
- 现有源码扫描测试的 `functionText(...)` 仍能找到原函数，断言不受影响；
- 改动集中在枚举与分发层，回归面最小。

```kotlin
// SettingsGroupRows.kt:61-73（示意）
SettingsGroup.SOURCES -> sourcesSections(vm) + contentSections(vm)
SettingsGroup.PLAYER -> playerSections(vm) + pictureSections(vm)
SettingsGroup.APPEARANCE -> appearanceSections(vm) + layoutSections(vm)
```

### 5.2 文件级清单

| 文件 | 改动 |
|---|---|
| `SettingsCommon.kt:33-53` | `SettingsGroup` 删除 `LAYOUT` / `CONTENT` / `PICTURE` 三个枚举；按 3.1 顺序重排为 8 项；注释 "twelve settings groups" 改为 eight |
| `SettingsGroupRows.kt:61-73` | `groupSections()` 删除已合并组的分支，改为 5.1 的 `+` 拼接 |
| `SettingsGroupRows.kt:423-455` | `contentSections()` 的 Section 标题由 `null` 改为 `settings_group_content_metadata`（合并后作为独立段落可辨识） |
| `SettingsGroupRows.kt:335-389` | `layoutSections()` 的 Section 标题由 `null` 改为 `settings_group_layout` |
| `SettingsPlayerRows.kt:79` | `pictureSections()` 的 eyebrow 由 `SettingsGroup.PICTURE` 改为 `SettingsGroup.PLAYER` |
| `SettingsPlayerRows.kt:107-131` | `soundSections()` 增加 OpenSubtitles 行（从 `contentSections` 搬入 `OpenSubtitlesViewModel` 的 collect 与判断），行 key 保持 `tab_OPEN_SUBTITLES` |
| `SettingsLeaf.kt:21-34` | `HOME` / `BROWSING` / `CONTENT_MENUS` 的 group 改为 `APPEARANCE`；`CUSTOMIZE` / `METADATA` 改为 `SOURCES`；`OPEN_SUBTITLES` 改为 `SOUND` |
| `customize/CustomizeItemsPane.kt:41`、`customize/CustomizeCategoriesPane.kt:84` | 面包屑硬编码 `SettingsGroup.CONTENT` 改为 `SettingsGroup.SOURCES` |
| `SettingsScreen.kt:48-52`、`MobileNavHost.kt:225` | 注释 "twelve groups" 改为 eight |

### 5.3 叶子页路由变化

`SettingsLeaf.route = "${group.route}/$slug"`，移动叶子页后路由随之改变：

| 叶子页 | 旧路由 | 新路由 |
|---|---|---|
| 首页 / 浏览与列表 / 内容菜单 | `settings/layout/*` | `settings/appearance/*` |
| 自定义 / 元数据 | `settings/content/*` | `settings/sources/*` |
| OpenSubtitles | `settings/content/opensubtitles` | `settings/sound/opensubtitles` |

全仓库没有硬编码这些路由的引用（仅 `SettingsLeaf.kt` 注释），路由由枚举统一注册（`MobileNavHost.kt:228-243`），无深链与持久化依赖。

## 6. 影响面与风险

| 项 | 结论 |
|---|---|
| 设置搜索 | 组页行读 `allGroupSections`，自动跟随；`LEAF_ROWS` 只引用 leaf 与 titleRes，不受 group 变化影响 |
| Quick 固定 | 行 key 全部不变，`allGroupSections` 覆盖 8 组后仍能找到全部行；`QUICK_ALIASES` / `QUICK_WORDS` 不动 |
| 备份 / TV 互认 | 只改 UI 分组，存储 key 与行 key 不变；备份导出不受影响 |
| 前三轮收敛 | `applySlimXxxDefaults` 与 `QUICK_TOGGLES` 均不涉及组结构，保持不变 |
| 第四轮观看与录制 | `watchingSections` 不动，目标结构不变 |
| 源码扫描测试 | `SlimPlaybackBehaviorDefaultsTest` 提取的 `playerSections` / `pictureSections` 函数体不变，断言继续通过；`SlimSoundDefaultsTest` 只匹配 `"vp_..."`，新增的 `tab_OPEN_SUBTITLES` 不进入断言；`SettingsSearchCoverageTest` 依赖的文件与索引不变 |
| i18n | 不删除行、不新增文案，`hardcoded_baseline.txt` 无需刷新；`MobileStringsParityTest` 不受影响 |
| 导航返回栈 | 升级瞬间不存在旧的 `settings/layout/*` 等返回栈；无持久化路由，无兼容处理需要 |

**唯一需要留意的编译点**：删除 `SettingsGroup.CONTENT` / `LAYOUT` / `PICTURE` 后，必须清干净所有引用（5.2 已列全：`SettingsLeaf.kt` 与两个 `customize/*.kt`）。可用 `grep "SettingsGroup\.(CONTENT|LAYOUT|PICTURE)"` 做编译前自检。
