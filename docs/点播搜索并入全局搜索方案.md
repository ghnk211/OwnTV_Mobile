# 点播页搜索并入全局搜索技术方案

> 对象：`OwnTV_Mobile`（`mobile-mini` 分支），只读依赖 `vendor/OwnTV_Core`（不改 Core）
> 范围：VOD（点播/TVbox）页内搜索入口与 `SearchScreen`（全局搜索）的合并
> 状态：方案稿（未实施）

---

## 1. 背景与目标

### 1.1 现状一句话

VOD 页的"搜索框"实际上不是一个搜索框：它是顶栏的一个放大镜按钮，点击后打开**页面内浮层**，浮层里再弹**一次性输入对话框**，对全部可搜索的 TVbox 站点做并发聚合搜索；而"全局搜索"是独立路由 `search?q=`，走 Core 的 `SearchReader` 搜**本地 Room 库**。两者除了共用输入组件 `StageSearchField` 外，**数据源、模型、过滤口径、导航、UI 全部独立**。

### 1.2 目标

1. **入口唯一**：VOD 页不再有第二个搜索入口，点搜索即进入全局搜索页。
2. **能力不减**：站点聚合搜索的能力（并发、流式先到先显示、按站点分组、儿童模式过滤）完整保留。
3. **体验一致**：输入、历史、空态/失败态、返回键行为与全局搜索统一。
4. **不动 Core**：全部改动落在 `app/` 内，不修改 `vendor/OwnTV_Core`、不改 Room schema、不把 TVbox 内容落库。

### 1.3 非目标

- 不做站点结果的**相关性混排**（本地结果与远端结果没有可比的相关性分）。
- 不做站点搜索的**分页**（引擎支持 `pg`，但当前调用方传 `null`；属后续能力）。
- 不改造 `VodScreen` 的"内部子状态机"整体架构（`docs/TVbox点播迁移方案.md` §"不新增顶层路由"仍有效，本方案只新增一个**详情**路由，见 §4.2）。

### 2.3 现存的直接问题（顺带要在合并中修掉）

1. **VOD 页有两个放大镜**：壳层顶栏 `ShellCluster` 的 `showSearch` 在 VOD 路由下为 `true`（`MobileShell.kt:489-492`），页面内又有一个（`TvboxPages.kt:338`），实际是两个功能不同、外观相同的搜索入口。
2. **VOD 搜索浮层没有 `BackHandler`**：系统返回键直接退出 VOD tab，而不是关闭浮层。
3. **死参数/死代码**：`onClearSearch`（`TvboxPages.kt:284、630`）、`TvboxHomeViewModel.clearSearch()`（`:391-393`）无真实调用路径。
4. **失败源静默**：`isSuccess` 过滤（`TvboxViewModels.kt:356、368`），UI 看不到"哪些源失败/预热中"，而 `SourceSearchResult.error` 已经带了原因。
5. **流式结果不可取消**：`aggregateSearch` 内部用注入的 `scope.async`（`SourceRepository.kt:397-398`），调用方取消协程不会取消站点请求；换关键词时旧请求继续跑完并继续 `tryEmit`。
6. **`SharedFlow` 全局串流**：`_searchProgress` 是 `SourceRepository` 单例上的一个 `SharedFlow`，若搜索页与 VOD 页同时搜索（迁移期并存），事件会互相污染。
7. **文档失真**：`extras/PARITY_CHECKLIST.md:58` 声称搜索"滚动到底加载下一页"，实现里没有分页。

## 3. 方案选型

### 3.1 候选方案

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 仅入口合并 | VOD 放大镜改成 `navigate(search)`，其余不动 | 站点搜索能力丢失（`SearchScreen` 不搜站点），不可接受 |
| **B. 统一搜索页 + 来源分段（推荐）** | 一个 `SearchScreen`，顶部"来源"维度：My library / Sites / All；两路各自取数、分区渲染 | 能力不减、UI 一套、风险可控、可分阶段上线 |
| C. TVbox 结果落库 | 把 `tvbox.Movie` 转成 `MovieEntity` 交给 `SearchReader` | 违反"不写 Core 表、不改 schema"；`String siteKey+vodId` 与 `Long id` 无法对齐；远端结果实时变化，落库即过期；**否决** |
| D. 搜索页只做壳，站点仍弹浮层 | 路由进搜索页后再弹回旧浮层 | 两套 UI 并存、Back 栈更乱，**否决** |

### 3.2 为什么选 B

- **不引入统一数据模型**：本地结果与站点结果分区渲染，避免为一个"混排"付出 sealed 行模型 + 排序策略的代价。
- **过滤口径按来源隔离**：本地沿用 `SearchReader` 的隐藏/改名/锁；站点沿用 `TvboxCategoryPolicy`，不互相污染。
- **可独立回滚**：来源维度默认 `MY LIBRARY`，与今日行为一致；站点来源可整体下线而不影响本地搜索。
- **分阶段可交付**：P0 先把"站点模式"搬进搜索页（功能等价迁移），P1 再做混合来源，P2 再打通详情直达。

## 4. 目标态设计

### 4.1 交互设计

```
┌─────────────────────────────────────────────┐
│  ‹ Back       Search                         │  ← 壳层 header（现状不变）
├─────────────────────────────────────────────┤
│  [🔍 Channels, movies and series        ✕ ]  │  ← StageSearchField（现状）
│  [ My library | Sites | All ]                │  ← 新增：来源分段（有站点时显示）
│  [ All | Live TV | TV Shows | Movies | … ]   │  ← 现有 SearchKind，仅作用于本地库
├─────────────────────────────────────────────┤
│  LIVE TV · 9                                 │
│  …（本地富行，现状）                          │
│  SITES · 3 sources · searching 2…            │  ← 新增：站点分组头
│  ── 本地CMS ─────────────────────────────    │
│  …（站点文字行，P2 升级为海报行）             │
│  ── 4K影视 ──────────────────────────────    │
│  …                                           │
└─────────────────────────────────────────────┘
```

规则：

| 场景 | 行为 |
|---|---|
| 从 VOD 放大镜进入 | 路由带 `src=sites`，来源默认 `Sites` |
| 从壳层/侧栏/Home/详情进入 | 默认 `My library`（与今日完全一致，不额外消耗流量） |
| 无任何可搜索站点 | "Sites"/"All" 分段不渲染，退化为今日的全局搜索 |
| 来源 = Sites | 隐藏 `SearchKind` 行（站点结果没有稳定媒资类型） |
| 输入长度 | 本地 ≥2（现状）；站点 ≥2 且 **800ms** 防抖（远端代价高，见 §4.6） |
| 历史 | 打开任一结果（本地或站点）都写 `recentSearches`；历史点选按"默认来源"重放 |
| Back | 有线选中过滤 → 清过滤；有非默认来源 → 回默认来源；否则退出搜索（替代现有浮层的无 BackHandler） |
| 空态 | 本地+站点都空 → 复用 `NothingFound`；仅站点空 → 站点分区内 `No results` |

### 4.2 路由设计

```kotlin
// MobileNavHost.kt
const val SEARCH_ROUTE = "search"                                   // 保持
private const val ARG_QUERY = "q"                                   // 保持
private const val ARG_SRC = "src"                                   // 新增
const val SEARCH_ROUTE_PATTERN = "search?q={q}&src={src}"          // 扩展
// src 取枚举小写名（"library"/"sites"/"all"），空串 = 默认 LIBRARY
fun searchRoute(query: String = "", src: SearchSourceTab? = null): String =
    "search?$ARG_QUERY=${Uri.encode(query)}" +
        (src?.let { "&$ARG_SRC=${it.name.lowercase()}" } ?: "")

// 新增：站点详情（仅用于跨页直达，属于子路由，不是新的顶层目的地）
const val VOD_DETAIL_ROUTE = "vod/detail"
const val VOD_DETAIL_ROUTE_PATTERN =
    "vod/detail?site={site}&id={id}&typeId={typeId}&typeName={typeName}"
fun vodDetailRoute(site: String, id: String, typeId: String = "", typeName: String = ""): String
```

注意：

- `q`、`src` 都有默认值（`defaultValue = ""`），`navigate("search")` 仍可匹配（现有 4 处调用点无需改动）。
- 新增 `src` 参数只影响初始来源，不写持久化偏好；不新增 deep link。
- `vod/detail` 的四个参数全部 `Uri.encode`；`typeId/typeName` 允许空串（搜索结果没有列表层分类身份，沿用 `TvboxDetailViewModel.open()` 的 R14 兜底口径）。
- `vod/detail` 与 `vod` 不是同一匹配（Nav 精确匹配），不会抢 VOD tab。

#### 4.3.1 接口定义

```kotlin
// ui/screens/search/RemoteSearchGateway.kt
enum class SearchSourceTab { LIBRARY, SITES, ALL }

/** 站点搜索对外暴露的事件流；全部为不可变快照，UI 无需理解 TVbox 细节。 */
sealed interface RemoteSearchEvent {
    data class Started(val siteCount: Int) : RemoteSearchEvent
    data class Group(val siteKey: String, val siteName: String, val rows: List<RemoteSearchRow>, val done: Boolean) : RemoteSearchEvent
    data class Failed(val siteKey: String, val siteName: String, val reason: String) : RemoteSearchEvent
    data object Finished : RemoteSearchEvent
}

data class RemoteSearchRow(
    val siteKey: String,
    val vodId: String,
    val title: String,
    val posterUrl: String?,
    val remark: String?,
    val year: String?,
    val typeName: String?,
)

interface RemoteSearchGateway {
    /** 当前档案下是否存在可搜索站点；false 时搜索页不渲染站点来源。 */
    val available: Flow<Boolean>
    /** 关键词 → 事件流；调用方取消即取消底层请求（依赖 §4.6 的 aggregateSearch 改造）。 */
    fun search(keyword: String): Flow<RemoteSearchEvent>
}
```

#### 4.3.2 搜索页状态模型

```kotlin
// SearchViewModel 内新增
private val _source = MutableStateFlow(SearchSourceTab.LIBRARY)
val source: StateFlow<SearchSourceTab> = _source.asStateFlow()

data class RemoteSearchUiState(
    val started: Boolean = false,          // 至少发过一轮
    val done: Boolean = false,
    val siteCount: Int = 0,
    val groups: List<RemoteSearchGroup> = emptyList(),
    val failed: List<RemoteSearchFailure> = emptyList(),
)

val remote: StateFlow<RemoteSearchUiState> = combine(
    _query.map { it.trim() }.debounce(REMOTE_DEBOUNCE_MS).distinctUntilChanged(),
    _source,
    ctx,
) { q, src, c -> Triple(q, src, c) }
    .flatMapLatest { (q, src, _) ->
        if (q.length < MIN_QUERY || src == SearchSourceTab.LIBRARY) flowOf(RemoteSearchUiState())
        else remoteSearch.search(q).runningFold(RemoteSearchUiState()) { acc, e -> acc.reduce(e) }
    }
    .stateIn(viewModelScope, SharingStarted.WhileSubscribed(5_000), RemoteSearchUiState())
```

要点：

- `flatMapLatest` 保证换词即取消上一轮（前提是 `aggregateSearch` 可取消，见 §4.6）。
- 本地 `results` 保持现状不变，**不把远端结果塞进 `SearchResults`**。
- 来源为 `LIBRARY` 时不对远端发请求；来源为 `ALL` 时两路并行。

### 4.5 过滤与合规

| 来源 | 过滤链 |
|---|---|
| 本地库 | `SearchReader`：`CustomizationStore` 隐藏/改名/锁 + 隐藏分类 + `AdultCategoryClassifier`（不改） |
| 站点 | `TvboxCategoryPolicy.visibleSites` → `movieAllowed`；站点 `adult/nsfw` 整站不参与（`SourceRepository.aggregateSearch:375` 已过滤）+ 结果行 `Movie.typeName` 二次过滤 |

- 儿童档案下，"Sites"来源的站点集合 = `policy.visibleSites(profile, configRepository.sites)` ∩ `canSearch` ∩ `isSupported`。
- **不允许**在 gateway 里另写一套词表或放宽过滤；必须复用 `TvboxCategoryPolicy` 单点判定。
- 详情层仍由 `TvboxDetailViewModel.open()` 二次校验（`TvboxViewModels.kt:494-523`），路由化不改变该口径。

### 4.6 并发、性能与取消

现状问题与改法：

```kotlin
// 现：SourceRepository.aggregateSearch（不可取消 + 全局 SharedFlow）
val results = ready.map { site ->
    scope.async { … }
}
awaitAll(*results.toTypedArray())

// 目标：改为调用方作用域 + 可选进度回调；保留旧签名兼容
suspend fun aggregateSearch(
    keyword: String,
    quick: Boolean = false,
    onlySiteKeys: Set<String> = emptySet(),
    concurrency: Int = SEARCH_CONCURRENCY,
    onProgress: ((SourceSearchResult) -> Unit)? = null,
): List<SourceSearchResult> = coroutineScope {
    …
    val results = ready.map { site -> async { … onProgress?.invoke(item) ?: _searchProgress.tryEmit(item) … } }
    awaitAll(*results.toTypedArray())
}
```

收益：

1. `flatMapLatest` 取消 → `coroutineScope` 内所有 `async` 一起取消，旧关键词请求真正停止；
2. 搜索页用 `onProgress` 回调，不再与 VOD 页（迁移共存期）争抢同一个 `SharedFlow`；
3. `_searchProgress` 保留给尚未迁移的 `TvboxHomeViewModel.search()`（P0 阶段后再删）；
4. `call()` 的 `Semaphore` 与 `withTimeoutOrNull` 无需改动，但要在 `call` 入口加 `coroutineContext.ensureActive()`，避免取消后仍占许可。

其它参数：

| 项 | 本地 | 站点 |
|---|---|---|
| 防抖 | 300ms（现状） | 800ms |
| 最小长度 | 2（现状） | 2 |
| 单轮并发 | — | `SEARCH_CONCURRENCY = 6`（现状） |

## 7. 分阶段实施

### P0：入口迁移（功能等价）

**目标**：删掉 VOD 浮层，搜索能力原样搬到搜索页的 `Sites` 来源。

## 8. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 远端搜索拖慢搜索页 | 打开搜索页即打十几个站点 | 默认来源 `My library`；站点 800ms 防抖；仅在来源含 Sites 时请求 |
| 改词后旧请求继续跑 | 结果错乱、源站压力、状态串 | P1 的 `coroutineScope` + `flatMapLatest`；`call()` 加 `ensureActive()` |
| `SharedFlow` 串流 | 两个入口同时搜索时互相污染 | `onProgress` 回调优先，`SharedFlow` 仅兼容保留 |
| 详情路由化破坏 VOD 内部状态机 | VOD 首页海报点击行为变化 | 双通道：VOD 内部 `DETAIL` 不动，`vod/detail` 只服务跨页跳转 |
| 儿童模式口径漂移 | 成人内容穿透 | 只复用 `TvboxCategoryPolicy`，禁止新词表；单测覆盖 |
| 站点结果与本地结果视觉不齐 | 体验割裂 | P2 富行统一版式；P0 阶段明确"文字行"是过渡态 |
| 文案遗漏语言 | 中文界面出现英文 | 三个 `values-*` 同步；`lint` 的 `MissingTranslation` 作为门禁 |
| 历史来源丢失 | 从历史重放时不知道搜哪个来源 | 历史只存关键词，重放按当前默认来源（已与今日一致） |

### 回滚策略

- 来源维度默认 `LIBRARY`，且 `available=false` 时不渲染分段 → 站点来源可整体关闭。
- `SearchSourceTab.SITES` 的入口只有一个（VOD 放大镜），回滚即恢复 `TvboxHomePage` 的原按钮与浮层；`TvboxSearchPage` 在 P2 前可保留为 `@Deprecated` 私有组件，P2 再删。
